# UScreen 0.2.0-preview.2

Second public preview. The macOS host is rebranded internally to match its own bundle
version, and the Android receiver ships for the first time.

## Downloads

| Asset | Size | Notes |
|---|---|---|
| `UScreen-0.2.0-preview.2-macos-arm64.zip` | 2.3 MB | `UScreen.app`, `INSTALL.txt`, `LICENSE` |
| `UScreen-0.2.0-preview.2-android.apk` | 1.5 MB | `com.uscreen` 0.2.0-preview.2, versionCode 20, Android 8.1+ |

Both are signed with project-local self-signed keys. The macOS app is not notarized.
The APK is not signed by the upstream author, so a tablet carrying an upstream build
must uninstall it first.

## What changed

- **Version identity.** `uscreen-macos --version` reported `0.1.0` while the bundle
  reported `0.2.0`; both report `0.2.0` now, bundle build `2026.10.25.2`.
- **Android receiver published.** Release build (R8 + resource shrinking), signed with
  a new local release key, APK Signature Scheme v2 + v3. Version aligned with the
  product: `0.2.0-preview.2` (versionCode 20); upstream lineage is `1.2.10`.
- **Privacy of the binary.** The release backend is built with `--remap-path-prefix`,
  so no builder home path is embedded. The device serial appears nowhere.
- **Licence in the archive.** `LICENSE` (MIT, upstream copyright) ships with the app.

## Verification performed

- 894 hardware-free Rust tests pass; the Swift menu-bar self-test passes, including the
  stale-permission and stale-manager regressions.
- All four macOS code signatures verify and satisfy their designated requirements.
- The installer was exercised into a temporary root: backend, native dylib, two
  LaunchAgents, install marker; launchd plists lint; no auto-connect flag; quarantine
  preserved; `setup uninstall` removes everything.
- The archive was re-extracted and re-verified (signature, version, self-test, install).
- The APK reports `com.uscreen` 0.2.0-preview.2 (20) and verifies under `apksigner`
  with v2 and v3 signatures.

## Hardware acceptance (measured, one session)

The published packages — not development binaries — were installed on the reference
machine and the tablet and exercised once, end to end:

- **Extended display.** A virtual extended display was created at 1600×960 @ 60 Hz and
  removed cleanly on stop. Exactly one UScreen display was present at any time; the
  machine's own displays were untouched.
- **Video.** The operator confirmed the live Mac desktop on the tablet, and a window
  dragged from the MacBook appeared on the tablet display.
- **Touch.** The operator confirmed that a tap moved the Mac pointer to the correct
  desktop position and that touch-dragging moved a window.
- **Measured rate.** 17.6–38.4 fps captured and 18.0–37.8 fps acknowledged while a
  window was moving, 0 blank and 0 dropped frames, frame age 32 ms p50 / 95 ms p95,
  tablet decode 29 ms, ~1.1 frames in flight. 60 fps was **not** reached.
- **Safety.** The independent supervisor ran throughout and recorded the ColorSync
  profile rate, the display-server and ColorSync CPU, memory pressure and the swap
  delta. The profile rate exceeded the machine's baseline band during the session
  (69/min against a 34/min ceiling); in the sampled window 25 of 75 profile creations
  were attributed to the virtual display and 50 to the two physical displays. ColorSync
  CPU stayed between 0.1 % and 6.7 %, well below the abort threshold.
- **Shutdown.** The operator ended the session; the host exited, the virtual display
  disappeared, the tablet stream was disconnected, the creation ledger gained exactly
  one entry, the operator's display lease was exhausted (1 of 1 session used), the
  single-use commissioning authorization became terminal, and the pre-existing
  quarantine record was left byte-identical. The connection agent remained blocked and
  started no further host.

## Not verified

- **Long-term stability.** The session lasted about three minutes. Multi-hour or
  multi-day operation is not demonstrated.
- **One machine only.** M1 Pro, macOS 26.5.1, DOOGEE U12 over USB, 1600×960.
- The macOS app remains not notarized: first launch requires a per-app override.
- The receiver was exercised with a release-signed APK for the first time; the earlier
  live figures in [Performance](../performance.md) come from older builds.

## Requirements

Apple Silicon Mac, macOS 13 or newer; Android 8.1+ tablet with USB debugging; a USB
data cable. One hardware combination has been exercised: M1 Pro, macOS 26.5.1,
DOOGEE U12 at 1600×960.
