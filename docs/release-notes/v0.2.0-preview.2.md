# UScreen 0.2.0-preview.2

Second public preview. The macOS host is rebranded internally to match its own bundle
version, and the Android receiver ships for the first time.

## Downloads

| Asset | Size | Notes |
|---|---|---|
| `UScreen-0.2.0-preview.2-macos-arm64.zip` | 2.3 MB | `UScreen.app`, `INSTALL.txt`, `LICENSE` |
| `UScreen-0.2.0-preview.2-android.apk` | 1.5 MB | `com.uscreen` 0.2.0-preview.2, versionCode 20, Android 8.1+ |

Both are signed with project-local self-signed keys. The macOS app is not notarized.
The APK is not signed by the upstream author, so a tablet carrying an upstream build
must uninstall it first.

## What changed

- **Version identity.** `uscreen-macos --version` reported `0.1.0` while the bundle
  reported `0.2.0`; both report `0.2.0` now, bundle build `2026.10.25.2`.
- **Android receiver published.** Release build (R8 + resource shrinking), signed with
  a new local release key, APK Signature Scheme v2 + v3. Version aligned with the
  product: `0.2.0-preview.2` (versionCode 20); upstream lineage is `1.2.10`.
- **Privacy of the binary.** The release backend is built with `--remap-path-prefix`,
  so no builder home path is embedded. The device serial appears nowhere.
- **Licence in the archive.** `LICENSE` (MIT, upstream copyright) ships with the app.

## Verification performed

- 894 hardware-free Rust tests pass; the Swift menu-bar self-test passes, including the
  stale-permission and stale-manager regressions.
- All four macOS code signatures verify and satisfy their designated requirements.
- The installer was exercised into a temporary root: backend, native dylib, two
  LaunchAgents, install marker; launchd plists lint; no auto-connect flag; quarantine
  preserved; `setup uninstall` removes everything.
- The archive was re-extracted and re-verified (signature, version, self-test, install).
- The APK reports `com.uscreen` 0.2.0-preview.2 (20) and verifies under `apksigner`
  with v2 and v3 signatures.

## Not verified

- **Neither artifact has been through a hardware session after this rebuild.** The
  performance figures in [Performance](../performance.md) come from the same source
  lineage on the reference machine.
- The APK has not been installed on a tablet for this build.
- The macOS app remains not notarized: first launch requires a per-app override.

## Requirements

Apple Silicon Mac, macOS 13 or newer; Android 8.1+ tablet with USB debugging; a USB
data cable. One hardware combination has been exercised: M1 Pro, macOS 26.5.1,
DOOGEE U12 at 1600×960.
