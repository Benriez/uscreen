# 0.3.0-dev.2 — Development channel

Released 2026-10-26 as a pre-release. Not hardware-tested. Not a replacement for
`v0.2.0-preview.3`.

## The defect in 0.3.0-dev.1

The Development LaunchAgents were installed into `~/Library/LaunchAgents` with
`RunAtLoad` and `KeepAlive`, exactly like Stable. launchd loaded both channels
at login and restarted them whenever they exited. Two supervisors and two
connection managers then competed for one physical display, and whichever lost
the race reported a ColorSync rate it could not have measured. Identity
isolation does not survive shared activation.

## The fix

- **Install is inert.** Development plists are staged in
  `~/Library/Application Support/uscreen-dev/services/`, which launchd never
  scans. `setup install --activate` is refused for this channel.
- **No auto-start, no respawn.** `RunAtLoad false`, no `KeepAlive`.
- **A live session is required.** `uscreen-macos dev start --authorize --serial
  <S>` loads both jobs and writes an expiring session (default 2 h, max 8 h)
  bound to the installed backend's SHA-256. The Development manager refuses to
  run without it and stops itself when it expires.
- **Hardware priority is enforced.** `dev start` refuses while another host
  holds the instance lock or a display is online. It reports the owner; it never
  kills it and never deletes a lock.
- **`dev stop`** boots out, disables, deletes the copied plists and clears the
  session — `.dev` labels only. **`dev status`** is read-only.
- **`setup install --migrate`** removes legacy Development agents from
  `~/Library/LaunchAgents` for people coming from `dev.1`. Stable is never
  touched.

## Verification

- 1017 hardware-free Rust tests pass; 27 are new isolation tests.
- `codesign --verify --strict` 4/4; APK Signature Scheme v2 + v3 with the same
  project key.
- 0 occurrences of the build machine's home directory in the shipped backend.

## Known limitations

- **Not tested on hardware.** No Connect/Disconnect was performed for this
  build.
- **Not notarized.** Local self-signed identity; macOS will ask you to allow the
  app.
- **No OS sandbox.** Isolation is application-level; both channels run as your
  user.
- The hardware acceptance run is still open: `retest prepare` refuses with
  `BASELINE_MISSING` until a fresh baseline is recorded.
