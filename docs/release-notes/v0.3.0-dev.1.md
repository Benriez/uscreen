## What is new

**Fixed**

- The normal-Disconnect quarantine race. The supervisor composed one
  observation out of probes taken seconds apart: the lifecycle record was read
  at the start of its tick and the display was probed at the end. A tick that
  landed inside a teardown saw "the host holds the lock, the lifecycle says
  RUNNING, the display is gone" — which is the invariant that means "a failed
  host" — and quarantined the machine after an ordinary Disconnect. The
  display probe and the lifecycle read are now adjacent, a shutdown
  announcement must have been published *before* the display went away, and
  the teardown window is bounded on a system-wide monotonic clock. A genuinely
  orphaned, crashed or stuck host still triggers the safety controller.
- A host that holds the instance lock no longer blocks the product for ever;
  the operator's one-shot arm is no longer swallowed by the lock state.
- The start gate and the operator's acceptance name the same conditions, so a
  test that was accepted is not refused at the start.

**Added**

- Stable and Development are separated by construction. The channel is
  compiled into the binary, so a development build cannot write into the
  recommended installation. The install roots, bundle identifiers, launchd
  labels, configuration, diagnostics and the Android application id are
  separate.
- The hardware authority is shared, not duplicated: one instance lock, one
  creation ledger, one product lease, one quarantine for the machine. Two
  hosts can therefore never compete for one display.
- Installation transactions are serialized machine-wide with an advisory lock.
  A promotion, a recovery and a development install cannot interleave their
  file copies.
- The installed Stable payload carries a recorded fingerprint that can be
  verified at any time, and the rollback artifacts are protected.

## Known limitations

- Apple Silicon Macs only, over USB.
- The macOS app is not Apple-notarized; macOS will ask you to allow it.
- Screen Recording and Accessibility permissions are required.
- Hardware compatibility is not universal.
- Amazon Prime Video and other DRM-protected playback may show black video
  while UScreen is active.
- The recommended build's Disconnect quarantine defect is fixed here, but the
  fix has not yet been accepted on hardware.
