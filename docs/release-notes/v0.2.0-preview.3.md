# UScreen 0.2.0-preview.3

This build makes a normal, operator-initiated connection work — and keep working.
Preview.2 could be connected once; after a failed start it could not be connected
at all without a quarantine clearance, and a session that did start was a bounded
controlled test rather than a product session.

## What was wrong

Five defects, all found by using the product rather than by reading it:

1. **The supervisor judged any lock holder as a host.** A diagnostic (`doctor`,
   `bench`, `setup status`) takes the same instance lock as the host. With a stale
   lifecycle record lying around, the supervisor judged that diagnostic by the
   heartbeat of a host that never ran — a critical condition that quarantined the
   machine and blocked every later connection.
2. **The ColorSync band compared the wrong quantities.** The baseline is the
   machine's churn *without* a UScreen display; the observation was the machine's
   churn *with* one. Any display that caused churn at all breached the band.
   Measured on this machine: the other two displays churn at 46–74/min on their
   own, and the virtual display adds 23–72/min depending on how much of the
   screen changes.
3. **A normal connection could not start while an advisory was present.** The
   operator's product lease did not satisfy the advisory readiness set, so every
   connection was forced through a *bounded* controlled retest — a second Touch ID
   prompt, a grant whose accepted advisories could go stale between the scan and
   the start, and a session that ended by itself.
4. **A cleared quarantine left the manager blocked.** The manager remembered the
   quarantine it had seen. After the operator cleared it — the documented way out
   — the manager ignored every later arm, and an arm that arrived while the
   manager was still settling was dropped as well. Both cost a Connect that did
   nothing.
5. **After a clean disconnect the next Connect was ignored.** The product could be
   connected once and never again without unplugging the tablet.

## What it does now

- A host is recognised only by a **verified process identity**.
- The relative ColorSync band bounds **UScreen's own per-display contribution**,
  using the attribution the supervisor already collects. A storm — the measured
  incident was 1650 profiles/min — still escalates and still stops the host.
- The operator's **product lease** authorises a product session, and a product
  session runs **until it is stopped** (`SessionRuntimePolicy::UntilStopped`).
- Clearing a quarantine releases the manager; an arm in the settling window is
  recorded instead of dropped.
- Connect → Disconnect → Connect works on the same attachment.
- The manager's liveness is a **heartbeat** it touches on every poll, so a live
  manager is not mistaken for a dead one on a loaded machine.
- `uscreen-macos quarantine clear` is verified instead of blind: it refuses while
  a host or a UScreen display is alive, appends the record to the new
  append-only `quarantine-history.jsonl`, and reconciles a lifecycle record whose
  process is verified gone.

**Unchanged:** ColorSync CPU 50 %, profile rate 300/min, WindowServer CPU, memory
pressure, heartbeat, the singleton lock, the creation ledger and budget, the
quarantine semantics, and the commissioning model.

## Hardware acceptance (measured, on the published packages)

One attended product session on the published preview.3 packages: M1 Pro,
macOS 26.5.1, DOOGEE U12 over USB, 1600×960 @ 60 Hz, low-latency profile.

| Measurement | Value |
|---|---|
| Capture | 28.8 – 43.0 fps while content moved |
| Acknowledged | 28.0 – 42.8 fps |
| Blank / dropped frames | 0 / 0 |
| Frame age | 15.2 – 15.5 ms p50, 19 – 21 ms p95 |
| Capture age | 1.1 – 1.9 ms p50 |
| Tablet decode | 28.7 – 29.4 ms |
| Frames in flight | 0.2 |
| Session length | 11+ minutes, no automatic end |
| Extended display | genuine, 1600×960 @ 60 Hz, removed cleanly on disconnect |

Operator-confirmed: the live Mac desktop on the tablet, a window dragged from
the MacBook onto the tablet display, a tap moving the Mac pointer to the correct
position, and touch-dragging moving a window. The operator then disconnected
(display removed, ledger unchanged) and reconnected on the same attachment
without unplugging the tablet.

## Not verified

- Long-term stability. The session lasted about eleven minutes.
- One machine only: M1 Pro, macOS 26.5.1, DOOGEE U12 over USB.
- The app is still not notarized: first launch needs a per-app override.
