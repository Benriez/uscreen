Developer use case

An Android tablet can be both your external display and your AI development worker.

Plug a tablet into a MacBook Pro and you have a real extended macOS display. Open an SSH session into Termux on that same tablet and you have a second machine that runs its own coding agents — on its own CPU and memory, with the model called remotely. One device, two roles, no new hardware.

  • A real extended display
  • Agents that run on the tablet
  • Continue the work on another worker
Role 1 · Display

The external display

UScreen registers a genuine extended display with the Mac’s window server, streams it down the USB cable and turns taps on the glass back into pointer events.

UScreen · USB · adb reverse

Role 2 · Worker

The AI development worker

Termux, SSH and OpenCode run the agent and the tools it calls on the tablet’s own hardware, while the model is served remotely.

Termux · OpenSSH · OpenCode

01 — The reason

Why you would build this

The Mac is where the editor, the browser and the terminal live. It is also where every coding-agent session wants to run at the same time — and several of them competing for the same cores and the same memory is a real constraint, not a theory.

The usual answers each cost something: run fewer sessions at a time, keep the local model small, or buy a second machine. The first two take away the thing you wanted. The third costs money and desk space.

This setup uses the hardware that was already on the desk. A tablet has an ARM CPU with several cores, a few gigabytes of RAM, storage and a full operating system — and Termux gives it a Linux-like userland on top. So it can hold a project, run an agent, run the tools that agent calls, and keep working while the Mac is busy.

The goal is not a faster Mac. It is a second place where work can happen, without taking anything away from the Mac you are already using.

How it works in four steps

The agent starts in the project directory on the tablet. Its tools run there too, and the model is called on a remote endpoint.

OpenCode · model endpoint

Continue the work anywhere

The project directory is synchronized, so the same checkout is waiting on the other worker. Pick the session up there.

Syncthing · second worker

The display device and the compute device are the same tablet. The Mac’s keyboard drives a window on the tablet’s screen, and the agent answering it runs on the tablet’s own processor.

03 — The line

The line: what belongs to which tool

This is the part worth keeping straight, because three different pieces of software sit on the same desk and it is easy to credit the wrong one.

UScreen

The display, and only the display

  • Creates a genuine extended macOS display
  • Streams that display over the USB cable
  • Returns touch to the Mac
The Android worker

The agent and its tools

  • Termux gives the tablet a userland
  • SSH opens the door from the Mac
  • OpenCode runs the agent on the tablet
Project sync

The same files everywhere

  • Syncthing synchronizes the project, both ways
  • Git keeps the history the workers share
  • You choose which worker runs the session

What none of them does: UScreen does not host a model, does not distribute agents, does not synchronize files, and does not orchestrate workers. That is not a gap in the product — it is what keeps the setup inspectable.

05 — Architecture

How the pieces connect

Four channels, four different jobs. Confusing them is the most common mistake when a display, a shell, a folder and a model request all live on the same desk — so the diagram names each one.

06 — The payoff

What you gain

THE MAC

Less pressure on the Mac

Agent sessions and the tools they call run on the tablet, so the Mac keeps the editor, the browser and the terminal — and stays responsive while they run.

THE SCREEN

A second working surface

Not a mirror and not a small picture of the desktop: a real extended display, where a terminal, a review pane or a second window can live permanently.

THE PROJECT

A portable, synchronized workspace

The same source is on every worker, kept in step peer to peer. The project follows the work instead of living on one machine.

THE PICKUP

Continue on another worker

A session is not tied to one device. Move the work to the other worker and pick it up there, with the same files already in place.

THE HARDWARE

Equipment you already own

No second machine and no server. A tablet that was bought for reading and video becomes a working surface with its own CPU and memory.

What this does not do. It does not make the Mac’s memory pressure disappear — it moves part of it to another machine. And a tablet is not Mac-class performance. This is a workflow enhancement, not a replacement for the machine you type on.
07 — Practical notes

Notes that matter in practice

Synchronization is the part of this setup that can surprise you. Three rules keep it predictable, and they are worth copying.

SECRETS

Keep device-local secrets out

Secret-shaped files that are not part of the repository stay out of the shared folder, so a key never travels to another machine by accident. Tracked files always synchronize.

BUILD OUTPUT

Rebuild generated files locally

Dependencies, build output and platform-specific binaries are rebuilt on the device that needs them, not copied around between machines.

GIT

Treat repository metadata as local

A synchronized directory is not a substitute for a remote. Each device keeps its own history and talks to the remote the normal way, so a conflict can never rewrite committed history.

Two honest limits of file synchronization. It is not instantaneous — an edit can take seconds to reach the other machine. And it is not a merge algorithm: if two machines change the same file before the change has travelled, the conflict is resolved by hand.
What does not travel. The agent’s own conversation history and any agent-specific memory stay on the device that produced them. A session started on the tablet does not continue on the phone, and this article does not pretend otherwise.
08 — The honest part

What this is not

The value of this setup is only real if its limits are knowable in advance. Here they are.

PERFORMANCE

Not Mac-class performance

A tablet’s cores are slower and its memory is smaller. It is additional capacity of a different kind, not a replacement machine.

PLATFORM

Android is not Linux

Android uses Bionic rather than glibc. Tools that depend on glibc-specific behaviour need an Android-compatible build or a compatibility layer.

COVERAGE

Some tools are simply missing

Apple-only frameworks and desktop toolchains do not run on Android at all. The worker is a second location for supported work, not a second desktop.

BACKGROUND

Background limits apply

Android can end a persistent session when the app leaves the foreground or the screen goes off. A long-running worker has to be arranged deliberately.

THERMALS

Heat and battery matter

Sustained compile and test load throttles a tablet, and the tablet runs on battery. A long session is a warm device.

CONTENTION

Two workloads, one chip

Decoding the video stream and running an agent’s toolchain at the same time are two real jobs. They share memory bandwidth and thermal headroom.

NETWORK

Networking is separate work

The tablet needs its own route to the model endpoint and its own configuration. None of that comes with the display.

CHOICE

You choose the worker

There is no scheduler and no exclusive project lock. Which machine runs a session is decided by hand, every time.

09 — Closing

A second screen can be part of the machine

A second screen can be more than a display. With the right tools, the device behind that screen can become part of your development environment.

The setup works because the two halves stay separate. UScreen’s job is narrow and it does it properly: a real extended display, video over the cable that is already plugged in, and touch that comes back. The worker half is ordinary tooling — a userland, an SSH session, an agent, a folder — assembled by hand, on hardware that was already bought.

The tablet is not a second computer on the desk. It is the second screen, doing double duty, and it turns into a working surface without a second purchase.
